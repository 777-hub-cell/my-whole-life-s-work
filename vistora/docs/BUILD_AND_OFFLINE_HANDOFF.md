# VISTORA — build and offline handoff

This guide is intended for continuing development after disconnecting from ChatGPT. The code and original HTML prototype are committed to the GitHub repository.

## GitHub

- Repository: `777-hub-cell/my-whole-life-s-work`
- Working branch: `feature/vistora-kotlin-native-android-20261122`
- Android project: `vistora/android/`
- Original prototype: `vistora/reference/Vistora.prototype.html`

Do not switch to the Aharane production/deployment branch to build VISTORA. Keep the work isolated in the VISTORA branch.

## What is included

- Native Kotlin/Jetpack Compose Android application.
- Room-backed local library and episode notes.
- DataStore preferences.
- Home, Library, Discover, Stats, Settings, Title Details, My Notes, and add/edit title sheets.
- Manual progress, statuses, ratings, date tracking, Overall Thoughts, and per-episode notes.
- Explicit ZIP backup/restore using Android's document picker.
- Optional direct TMDB and AniList catalogue search.
- Keystore-encrypted TMDB credential storage.
- Original HTML and design/engineering specifications.
- GitHub Actions workflow for build, unit tests, instrumentation tests and Android lint.

## Build from a full repository checkout

The VISTORA wrapper delegates to the shared Aharane Gradle wrapper, so keep the complete repository checkout.

From the repository root:

```bash
bash vistora/android/gradlew :app:assembleDebug
```

Debug APK output:

```
vistora/android/app/build/outputs/apk/debug/app-debug.apk
```

The APK is not committed to source control. It is generated by the build.

## Verify

```bash
bash vistora/android/gradlew :app:testDebugUnitTest
bash vistora/android/gradlew :app:lintDebug
```

Room instrumentation tests require an Android emulator or connected Android device:

```bash
bash vistora/android/gradlew :app:connectedDebugAndroidTest
```

The workflow is in `.github/workflows/vistora-android.yml`. See the repository's Actions tab for the actual build result. Do not treat a committed workflow as proof that a build passed.

## Offline behaviour

The app stores titles, statuses, progress, ratings, dates, preferences, episode notes, overall thoughts, and poster copies on the device. These core features work without a network connection.

Discover can use direct public provider APIs when online:
- TMDB for films, TV series and K-dramas (user-supplied credential).
- AniList public GraphQL for anime (no user key required).

There is no VISTORA server, login, account, cloud database, or sync service. The Android INTERNET permission is only for optional catalogue discovery and image retrieval.

## Before a public release

- Confirm the GitHub Actions build, instrumentation tests and lint are green.
- Build and test the release variant with R8.
- Inspect on physical Android phones, including small screens and large font settings.
- Complete TalkBack/focus/contrast and reduced-motion checks.
- Add the current official TMDB logo asset in the About/attribution area as required by TMDB's current branding rules; keep the required text attribution.
- Review the current TMDB and AniList terms and rate limits.
- Test ZIP backup/restore round-trips using a library that includes posters and long episode notes.
